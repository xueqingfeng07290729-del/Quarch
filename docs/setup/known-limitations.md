## QTL2843 Ethernet

### 接线和已观察到的现象

| 组件 | 此次问题反馈中的配置 |
| --- | --- |
| 仪器 | Quarch QTL2843 |
| PoE Injector | Tenda PoE30G-AT |
| Injector 输出 | `DATA & PWR OUT` 连接 QTL2843 的 Ethernet / PoE 端口 |
| Injector 数据输入 | `DATA IN` 接 BUFFALO 交换机，或绕过交换机直接接 Linux 电脑 |
| 排查主机 | Dell Precision 5820，Linux，有线网卡 `eno1` |
| Linux 地址 | `192.168.1.10/24` |
| 仪器地址 | 经 USB 查询确认为 `192.168.1.99/24` |

两种尝试的网络路径为：

```text
交换机方案：BUFFALO 交换机 ↔ Injector DATA IN / DATA & PWR OUT ↔ QTL2843
直连方案：Linux eno1    ↔ Injector DATA IN / DATA & PWR OUT ↔ QTL2843
独立 USB 通信：Linux 电脑 ↔ USB ↔ QTL2843
```

QTL2843 和 Injector 均正常通电，USB 通信正常，但 Ethernet 始终无法建立物理链路。
现场报告的 Linux 网卡状态持续为 `NO-CARRIER`，链路查询为 `Link detected: no`；
通过 USB 查询仪器故障状态返回 `OK`。供电、USB 和仪器故障查询正常，尚不能证明 Ethernet 数据通路正常。

此处 Dell Precision 5820 属于 QTL2843 网络排查的现场记录；SSD/GPU 实验的主机环境以各自归档为准。

### 已经尝试的排查

| 序号 | 已执行的操作 | 结果 |
| --- | --- | --- |
| 1 | 更换 BUFFALO 交换机端口 | 所有尝试的端口均未建立链路 |
| 2 | 确认网线正常，排除明显线缆故障 | 链路仍未建立 |
| 3 | 绕过交换机，将 Linux 网卡直接连接 Injector 的 `DATA IN` | 仍无法建立链路 |
| 4 | 确认 Linux 网卡、Injector 和 QTL2843 均支持 100 Mbps | 未解决问题 |
| 5 | 关闭 EEE（Ethernet 节能功能） | 未解决问题 |
| 6 | 限制 Linux 网卡仅使用 100 Mbps 自动协商 | 仍无链路；之后已恢复原速率/协商设置 |
| 7 | 核对 Linux 地址，并经 USB 读取仪器 IP 配置和故障状态 | 地址同为 `192.168.1.0/24` 网段，故障状态为 `OK`；链路仍未建立 |

上表记录现场已做的尝试；没有把未执行的替换设备对照测试列为已完成。

### 当前判断和未确认原因

根据目前反馈，问题发生在 **Ethernet 物理链路建立阶段**，不是已建立连接后的 IP 配置问题或网络带宽不足。
现有尝试均未解决问题，尚未确定具体原因。目前保留的可能性为：

- PoE Injector 的数据传输通路异常。
- QTL2843 Ethernet 接口故障。
- Injector 与 QTL2843 之间存在互通或协商兼容性问题。

这些是待验证的假设，不能直接认定 Injector 或仪器已经损坏。
现有记录尚不足以在这几种原因之间作出判定；需要补充针对数据通路、仪器接口和设备组合的对照验证。

目前可用的是 **PoE 供电 + USB 命令与测量数据传输**，见 [QTL2843 接线记录](current-wiring.md)。
Ethernet 控制和采集尚未验证可用。后续应先确认物理链路可以稳定建立，再验证网络通信和实际采集。

<a id="m2-mounting"></a>

## M.2 SSD 夹具固定不稳

使用者反馈：**目前的 M.2 SSD 夹具无法将 SSD 固定在夹具上，只能依靠插槽本身的固定能力，固定非常不稳定。**
这意味着当前实际安装尚未实现可靠的机械固定，不能把接线步骤中的“插入并固定”理解成实物固定已经完成。
仓库此前识别的 M.2 夹具为 QTL2980-01，见 [M.2 设备身份与接线](qtl2312-m2.md)。

现阶段的不足是装配牢固性和重复安装的一致性。需要确认匹配的固定件、支撑方式及安装条件，
完成可靠固定后再验证实际使用的稳定性。目前尚未确认是固定附件、安装方式还是夹具适配方面的问题。
已有成功采集记录只能说明当时完成了通信和测量，不能代替机械固定验证；
也没有证据将已归档的 SSD 查询能耗波动直接归因于该固定问题。

<a id="pcie-mounting"></a>

## PCIe 设备安装与 20 cm 线缆限制

使用者反馈：**PCIe 夹具安装之后，很难再安装显卡和其他 PCIe 设备；新购夹具的 PCIe 线只有 20 cm，
在现有安装布局中长度不够，很难使用。** 这两项问题分别涉及设备安装空间和线缆可达范围，均尚未解决。

当前不足是夹具、被测卡和其他 PCIe 设备之间难以安排合适的位置，20 cm 线缆又限制了设备摆放和走线。
已有 RTX 5050 测量结果不代表这套夹具在现有布局中易于安装，也不能据此认为其他 PCIe 设备都能顺利安装。

后续需要补充新购夹具的完整型号、PCIe 线缆具体规格、实际布线路径及所需长度，
再确定匹配的安装和线缆方案。更长线缆方案尚未验证，其适配性和实际 PCIe 链路状态仍需确认。
已识别的 QTL2983 主夹具、AUX 子板及逻辑接线见 [PCIe / 显卡接线指南](qtl2312-gpu.md)。

## 已有实验的测量与证据限制

- **显卡功率差异仍未解释。** 首次矩阵负载 Quarch 平均约 105.639 W，三次复测平均约 108.652 W，
  NVIDIA 遥测均约 130 W。原始单位、时间戳和分路求和已核对，但物理供电路径覆盖、夹具配置和校准仍需核查。
  NVIDIA 遥测窗口与精确的 Quarch 采集窗口也没有严格对齐，不能将其中任一读数直接当作另一方的校准依据。
- **三次复测只说明本次短时重复性。** 三轮起始温度为 30–32°C，结束为 67°C；
  初始风扇百分比分别为 0%、31%、31%，环境与散热器温度未测量。0.0821% 的轮间变异系数不代表绝对精度或长期热稳态。
  方法、数据及完整边界见 [显卡实验归档](../../experiments/2026-11-11-rtx5050-gpu/README.md)。
- **SSD 查询波动与温度影响仍需进一步区分。** 原始 Q19/Q20 波动明显，Q19 增大间隔后结果更接近，
  但现有记录不能证明温度是唯一原因，也不能将其归因于夹具固定。69 次查询测量关闭逐点 CSV，
  保留的是在线积分 JSON，无法从原始波形重新积分各查询；硬件短测另有 CSV。
  详见 [SSD 实验归档](../../experiments/2026-11-09-tpch-sf30-ssd/README.md)。

上述问题记录不改变已归档的原始测量值。问题修复或复测后，应另行记录变更、验证条件和结果，保留此前状态供对照。
